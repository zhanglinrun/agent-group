# 秋招项目最终证据报告

这份文档是本轮优化后的最终证据口径，用来对应简历亮点、测试命令、可写数字和演示路径。旧的阶段性性能口径不再作为简历依据；没有实测来源的数字不写入简历。

## 一、本轮最终结论

本轮已补完三条面试可验证证据主线：

- `Agent`（智能体）运行账本：一次任务可以按 `runId`（运行编号）查到模式、计划、工具调用、失败、重规划、诊断和额度消耗。
- 交易只读审计：按订单聚合订单、支付、拼团、退款、额度流水和核对结论，前端与 `Agent`（智能体）不直接决定额度到账。
- `RAG`（检索增强生成）最小证据：知识库文档能展示解析状态、向量入库状态、失败原因和引用片段。

本轮不扩展模型能力配置、复杂模型路由、额度倍率配置，也不把只读审计做成运营操作台。

## 三、Agent 运行账本证据

### 能力结论

已完成 `Agent`（智能体）运行详情的后端证据闭环。现在可以通过 `runId`（运行编号）查询一次任务的核心证据：执行模式、计划版本、计划步骤、工具调用、失败原因、重规划次数、诊断结果、模型调用、产物和额度消耗。

涉及接口：

```text
GET /api/v1/academic/runs/{runId}
```

接口返回的运行详情中包含：

- `evidence`（运行证据摘要）
- `diagnosis`（诊断报告）

### 覆盖用例

| 用例 | 验证点 | 结果 |
| --- | --- | --- |
| 正常运行详情 | `runId` 能查到模式、计划、工具、诊断和额度证据 | 通过 |
| 工具失败后恢复 | 失败工具进入 `failedTools`，后续成功工具形成重规划证据 | 通过 |
| 诊断报告 | 根据工具失败、重规划、耗时和额度生成诊断指标 | 通过 |

## 四、交易一致性证据

### 能力结论

已完成交易只读审计的后端证据闭环。管理端可以通过订单、用户或分页条件查询交易核对结果，返回订单、支付单、退款单、额度到账流水、退款回滚流水和当前结论。

涉及接口：

```text
POST /api/v1/trade/order/admin/audit
```

接口只读取后台事实，不提供补发额度、退款、手动补偿等写操作。返回结果中包含：

- `facts`（事实快照）：订单状态、支付状态、退款状态、额度到账流水、退款回滚流水。
- `quotaGrantAllowed`（是否允许发放额度）：由后端交易状态判断，前端不参与推断。
- `refundRollbackRequired`（是否需要额度回滚）：用于定位退款后额度流水缺失。
- `settlementLabel`（核对标签）和 `settlementDetail`（核对说明）：用于管理端只读展示。

### 覆盖用例

| 用例 | 验证点 | 结果 |
| --- | --- | --- |
| 拼团支付成功但未成团 | 返回 `WAIT_GROUP_SETTLEMENT`，`quotaGrantAllowed` 为 `false` | 通过 |
| 直购支付成功但未到账 | 返回 `QUOTA_GRANT_REQUIRED`，`quotaGrantAllowed` 为 `true` | 通过 |
| 拼团成团但未到账 | 成团后才允许发放额度，返回 `QUOTA_GRANT_REQUIRED` | 通过 |
| 拼团成团且已到账 | 额度到账流水存在时返回 `QUOTA_GRANTED_CONSISTENT` | 通过 |
| 退款后缺少回滚流水 | 返回 `REFUND_ROLLBACK_REQUIRED`，`refundRollbackRequired` 为 `true` | 通过 |
| 订单和支付状态冲突 | 返回 `TRADE_STATE_CONFLICT`，禁止发放额度 | 通过 |

### 前端展示

已完成管理端交易只读审计展示。管理后台加载时会读取最近 20 条审计结果，在订单监控后展示核对结论、说明、是否允许发放额度、是否需要回滚和事实快照。

演示位置：

```text
管理后台 -> 交易订单监控 -> 交易只读审计
```

前端只展示后端审计接口返回的数据，不提供补发额度、退款、手动补偿或批量处理入口。

## 五、RAG 最小证据

### 能力结论

已完成 `RAG`（检索增强生成）的最小证据闭环。本轮只做文件处理状态、入库状态、失败原因和引用片段展示，不扩展入库补偿队列或运营处理台。

涉及接口：

```text
GET /api/v1/knowledge/document/list
GET /api/v1/knowledge/document/full-content?documentId={documentId}
GET /api/v1/knowledge/document/fragments?documentId={documentId}
```

接口返回结果中包含：

- `parseStatus`（解析状态）：是否已经生成可引用片段。
- `embeddingStatus`（向量入库状态）：`READY`（可检索）、`FAILED`（入库失败）、`PENDING`（等待处理）、`DISABLED`（已停用）。
- `retrievalReady`（是否可检索）：由文档状态、启用状态和片段数量共同判断。
- `failureReason`（失败原因）：用于说明未入库、入库失败或停用原因。
- `citationLabel`（引用标签）和 `citationSnippet`（引用片段）：用于回答引用证据展示。

### 覆盖用例

| 用例 | 验证点 | 结果 |
| --- | --- | --- |
| 文档全文查询 | 按片段顺序返回全文、解析状态、向量状态和引用片段 | 通过 |
| 向量入库失败 | 返回 `FAILED` 和“向量入库失败”原因 | 通过 |
| 文档停用 | 返回 `DISABLED`，且 `retrievalReady` 为 `false` | 通过 |
| 管理端展示 | 知识库表格展示解析、向量、可检索、失败原因和引用证据 | 通过 |

演示位置：

```text
管理后台 -> 知识库向量管理 -> 查看文档解析/向量状态 -> 点击“查看”展示引用片段
```

本轮只做最小证据展示，不做新的补偿队列、批量重试策略或模型路由配置。


## 八、本轮暂缓项

模型能力配置、模型路由、额度倍率配置本轮暂缓。原因是它们对当前秋招主线的证明价值低于运行账本、交易一致性和 `RAG`（检索增强生成）证据，且容易把范围扩大成新一轮产品化开发。

旧版 `docs/PERFORMANCE_REPORT.md`（性能报告）已删除。该文件包含未重新验证的性能和成本数字，容易和本报告的“只保留可复现证据”口径冲突。
