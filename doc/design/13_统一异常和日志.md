# 统一异常和日志

## 一、目标

后端接口统一返回 `Response` 响应体，并在每次请求中带上 `requestId`，方便前端展示错误信息，也方便后端按日志追踪一次请求。

## 二、请求追踪

客户端可以传入请求头：

```text
X-Request-Id
```

如果没有传，后端会自动生成一个。响应头和响应体都会返回同一个 `requestId`。

## 三、异常类型

| 类型 | 返回方式 |
| --- | --- |
| 业务异常 | 返回业务错误码和错误信息。 |
| 参数异常 | 返回 `0001` 和“参数错误”。 |
| 系统异常 | 返回 `9999` 和“系统繁忙，请稍后再试”。 |

## 四、当前范围

普通 HTTP 接口走全局异常处理。导购流式接口内部的业务失败仍按 `error` 流式事件返回，保证前端流式渲染不被中断。
