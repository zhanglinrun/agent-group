# 支付订单模型

## 一、目标

本阶段先建立交易订单和支付单的领域模型，固定直接购买、拼团购买、创建支付单、支付成功、未支付关闭和拼团结算的状态规则。

当前不接真实支付渠道，不落库，不处理真实回调，只保留后续接入支付和订单持久化所需的领域能力。

## 二、新增对象

| 对象 | 含义 |
| --- | --- |
| `TradeOrder`（交易订单） | 保存用户、商品、活动、购买类型、订单金额、支付金额和订单状态。 |
| `PayOrder`（支付单） | 保存支付单号、订单号、支付渠道、支付金额、支付状态、支付链接和外部交易单号。 |
| `TradePayOrder`（交易支付结果） | 一次创建支付单后的聚合结果，包含交易订单和支付单。 |
| `CreateTradeOrderCommand`（创建交易订单命令） | 创建订单时传入的用户、商品、活动和金额参数。 |
| `TradeOrderService`（交易订单服务） | 负责创建订单、创建支付单、支付成功和未支付关闭。 |

## 三、状态枚举

交易订单状态：

- `CREATE`（已创建）。
- `PAY_WAIT`（等待支付）。
- `PAY_SUCCESS`（支付成功）。
- `GROUP_SETTLED`（拼团已结算）。
- `DEAL_DONE`（交易完成）。
- `CLOSED`（已关闭）。
- `WAIT_REFUND`（待退款）。
- `REFUNDED`（已退款）。

支付单状态：

- `WAIT_PAY`（等待支付）。
- `SUCCESS`（支付成功）。
- `FAILED`（支付失败）。
- `CLOSED`（已关闭）。
- `REFUNDED`（已退款）。

## 四、当前状态规则

- 订单创建后进入 `CREATE`（已创建）。
- 创建支付单后，订单进入 `PAY_WAIT`（等待支付），支付单进入 `WAIT_PAY`（等待支付）。
- 支付成功后，订单进入 `PAY_SUCCESS`（支付成功），支付单进入 `SUCCESS`（支付成功）。
- 未支付订单可以关闭，关闭后订单进入 `CLOSED`（已关闭），支付单进入 `CLOSED`（已关闭）。
- 已支付订单不能关闭。
- 拼团订单在支付成功后可以进入 `GROUP_SETTLED`（拼团已结算）。
- 非拼团订单不能执行拼团结算。

## 五、测试范围

已在 `backend/agent-group-app/src/test/java`（后端测试目录）补充 `TradeOrderServiceTest`（交易订单服务测试）。

测试覆盖：直接购买订单、拼团订单、拼团缺少活动编号、支付金额非法、支付成功幂等、未支付关闭、已支付关闭失败、拼团结算、非拼团结算失败、订单和支付单不匹配。
