# 技术报告章节模板

本模板定义报告的标准骨架，适用于机器学习、系统工程、算法研究等各类技术项目。根据项目实际内容裁剪——并非所有项目都需要全部章节，但核心章节（标 ★）不可省略。

## 标准章节结构

```
# [项目名称]技术报告

## 1. 概述 ★
  （背景、问题、挑战、方案概述、数学问题定义、报告结构导读）

## 2. 数据与问题设定
  ### 2.1 数据来源与组织形式
  ### 2.2 数据统计特性与划分方式

## 3. 理论框架与方法设计 ★
  ### 3.1 问题定义
  ### 3.2 输入表示与预处理设计
  ### 3.3 模型/算法架构
  ### 3.4 目标函数与评估指标

## 4. 系统实现与工程细节 ★
  ### 4.1 系统架构与训练/运行配置
  ### 4.2 数据处理流水线与工程优化

## 5. 实验结果与分析 ★
  ### 5.1 定量结果分析
  ### 5.2 典型案例/可视化分析
  ### 5.3 本章小结
```

**章节适配说明**：不同类型的项目在骨架上做适当裁剪——

| 项目类型 | 第2章重点 | 第3章重点 | 第4章重点 |
|---------|----------|----------|----------|
| ML/DL 模型 | 数据集、标注、分布 | 网络结构、损失函数 | 训练配置、硬件 |
| 算法/优化 | 问题输入规模、benchmark | 算法设计、复杂度分析 | 实现语言、数据结构 |
| 系统/工程 | 需求、场景、约束 | 架构设计、协议 | 部署、性能调优 |
| 数据分析 | 数据采集、清洗 | 分析方法、统计模型 | 可视化工具链 |

## 各章写作要点

### 第1章 概述

本章是整篇报告的"电梯演讲"，读完概述应能回答：做什么、为什么难、怎么做、做得怎样。

**段落递进逻辑**（5 段）：
1. **领域背景**：说明应用场景的重要性与技术需求
2. **现有方法局限**：指出 2-3 个核心痛点，每个痛点独立分析
3. **本项目方案概述**：提出解决方案的核心设计理念，说明关键技术组件
4. **数学问题定义**：将问题形式化为数学表达式，定义输入输出变量
5. **报告结构导读**：说明后续各章的组织与逻辑

**注意**：概述中的问题定义是 informal 版本（给读者直觉），第3章的是 formal 版本（精确数学定义）。

### 第2章 数据与问题设定

**必须包含**：
- 数据来源（公开/自采/合成）与场景说明
- 数据格式（字段含义、类型、单位）——用文字精确描述
- 统计特性（规模、分布特征、典型值范围）——用表格呈现
- 划分方式（训练/验证/测试的划分策略与比例）——说明合理性

**表格格式规范**：

```markdown
**表2-1 [描述性标题]**

| 列名A | 列名B | 列名C | 列名D |
|-------|-------|-------|-------|
| 值    | 值    | 值    | 值    |
```

表格标题以 **"表[章号]-[序号] [描述]"** 格式命名。表格紧跟引用文字，之后 1-2 句话点明关键发现。

### 第3章 理论框架与方法设计

这是报告的核心智力密度最高的章节。

**3.1 问题定义**：
- 用数学语言精确定义输入、输出和目标
- 定义所有后续会用到的核心符号
- 给出优化目标的数学表达（分类→交叉熵、回归→MSE、生成→似然等）

**3.2 输入表示与预处理**：
- 特征工程（哪些特征、如何构造、为什么这么选）
- 归一化/标准化策略及其动机
- 样本构建策略（采样、增强、窗口化等）
- 每个设计决策都要说明 **为什么**（不只是 what，更要 why）

**3.3 模型/算法架构**：
- 按模块逐一展开，描述信息流
- 每个模块遵循：功能说明 → 数学公式 → 变量解释 → 设计动机
- 模块间的数据流转和维度变化要说清楚

**3.4 目标函数与评估指标**：
- 目标函数的完整数学表达式
- 各项损失的物理含义与权重设计的直觉
- 评估指标的数学定义与物理含义

### 第4章 系统实现与工程细节

**必须包含**：
- 编程语言、框架版本、硬件环境
- 关键超参数配置表（表格形式）
- 训练/运行策略（精度策略、梯度裁剪、早停、调度器等）
- 数据处理流水线的工程细节（缓存、采样策略、并行化等）

**参数表格规范**：

```markdown
**表4-1 关键参数配置**

| 参数 | 取值 | 说明 |
|------|------|------|
| [参数名] | [数值] | [一句话解释] |
```

### 第5章 实验结果与分析

**5.1 定量分析**的写作模式：
1. 训练/运行过程概述（收敛趋势、最优轮次等）
2. 全局指标总览（表格 + 解读）
3. 分组/分维度对比分析（找差异、给解释）
4. 与基线/SOTA 的对比（如适用）
5. 局限性诚实分析

**5.2 可视化分析**：
- 选取典型案例（最优、中位、最差，或有代表性的不同类型）
- 图表说明格式："如图X-Y所示，[观察到的现象]。[现象的解释]。[与定量指标的呼应]。"

**5.3 小结**：
- 用 3-5 句话概括本章发现
- 点明方法的有效性与局限
- 暗示未来改进方向

## 可选扩展章节

根据项目特点可增加：

| 扩展章节 | 适用场景 | 位置建议 |
|---------|---------|---------|
| **相关工作** | 偏学术、需对比前人方法 | 第2章之前 |
| **消融实验** | 需验证各模块贡献 | 5.x 子节 |
| **部署与推理优化** | 工程交付类项目 | 第4章之后 |
| **安全性与鲁棒性分析** | 涉及对抗场景 | 5.x 子节 |
| **总结与展望** | 篇幅较长的完整报告 | 最后一章 |
