# 直接购买下单

## 一、目标

本阶段实现从商品卡片发起直接购买下单。

当前只创建交易订单和模拟支付单，不接真实支付渠道，不处理支付回调，不进入拼团锁单。

## 二、接口

```text
POST /api/v1/trade/order/direct
```

请求参数：

| 字段 | 含义 | 是否必填 |
| --- | --- | --- |
| `userId`（用户编号） | 下单用户 | 是 |
| `goodsId`（商品编号） | 商品编号 | 是 |
| `payChannel`（支付渠道） | 支付渠道，不传时使用模拟支付 | 否 |

返回结果：

| 字段 | 含义 |
| --- | --- |
| `orderId`（订单编号） | 交易订单编号。 |
| `payOrderId`（支付单编号） | 支付单编号。 |
| `orderStatus`（订单状态） | 当前为等待支付。 |
| `payStatus`（支付状态） | 当前为等待支付。 |
| `originAmount`（订单原价） | 商品原价。 |
| `payAmount`（支付金额） | 当前直接购买时等于商品原价。 |
| `payUrl`（支付链接） | 当前为模拟支付链接。 |

## 三、落库表

新增两张表：

- `trade_order`（交易订单表）：保存用户、商品、购买类型、订单金额、支付金额和订单状态。
- `pay_order`（支付单表）：保存支付单号、订单号、支付渠道、支付金额、支付状态和支付链接。

`Mapper XML`（映射文件）放在 `agent-group-app/src/main/resources/mybatis/mapper`（应用模块资源目录）。

`Java DAO`（数据访问接口）放在 `agent-group-infrastructure`（基础设施模块）的 `dao`（数据访问）包。

## 四、当前规则

- 下单时后端按 `goodsId`（商品编号）读取商品，不信任前端传入价格。
- 直接购买订单的支付金额等于商品原价。
- 创建订单后，交易订单进入 `PAY_WAIT`（等待支付）。
- 创建支付单后，支付单进入 `WAIT_PAY`（等待支付）。
- 商品不存在或下架时返回 `DATA_0003`（商品不存在或已下架）。
