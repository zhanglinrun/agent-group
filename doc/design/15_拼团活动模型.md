# 拼团活动模型

## 一、目标

本阶段先建立拼团活动的基础领域模型，用于后续导购卡片、拼团试算、锁单和支付流程。

当前只判断活动是否可用，不创建订单，不占用名额，也不处理支付。

## 二、新增对象

| 对象 | 含义 |
| --- | --- |
| `GroupBuyActivity`（拼团活动） | 保存活动编号、商品编号、拼团价、成团人数、开始时间、结束时间和启用状态。 |
| `GroupBuyActivityStatus`（拼团活动状态） | 包含可用、未开始、已结束、已停用、未配置。 |
| `GroupBuyTrialResult`（拼团试算结果） | 返回商品编号、活动编号、拼团价、成团人数、剩余秒数、状态和提示信息。 |
| `GroupBuyActivityRepository`（拼团活动仓储接口） | 领域层只依赖仓储接口，不直接依赖数据库。 |
| `GroupBuyActivityService`（拼团活动服务） | 负责按商品编号试算拼团活动状态。 |

## 三、数据库接入

`Java DAO`（数据访问接口）放在 `agent-group-infrastructure`（基础设施模块）的 `dao`（数据访问）包下。

`Mapper XML`（映射文件）放在 `agent-group-app/src/main/resources/mybatis/mapper`（应用模块资源目录）下，保持和参考项目的组织方式一致。

## 四、状态规则

- 活动未配置：返回 `MISSING`（未配置）。
- 活动关闭：返回 `DISABLED`（已停用）。
- 当前时间早于开始时间：返回 `NOT_STARTED`（未开始）。
- 当前时间达到或超过结束时间：返回 `ENDED`（已结束）。
- 其余情况：返回 `ACTIVE`（可用）。
