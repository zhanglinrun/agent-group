# Agent 平台能力补强路线

本文用于约定从 `ai-agent`（参考智能体项目）借鉴能力时的落点，避免把当前项目从“学术 `Agent`（智能体）额度与拼团交易系统”改散。

## 总目标

最终项目定位为：强 `Agent`（智能体）能力 + 强交易闭环。

- `Agent`（智能体）侧补齐通用运行时、工具编排、产物登记、历史回放、多模态和数据分析能力。
- 交易侧继续保持额度、拼团、支付、退款、通知补偿和状态一致性优势。
- 两条线通过额度消耗、运行账本、工具产物、订单状态连接，避免变成两个无关系统。

## 能力迁移顺序

1. 运行时底座
   统一工具定义、工具集合、产物登记、受控执行器、运行账本和回放投影。

2. 工具体系
   补齐工具元数据、按场景装配、并发执行、结构化输出、统一失败语义。

3. `MCP`（模型上下文协议）
   从当前内置工具列表升级为可注册、可发现、可缓存、可开关的 `MCP`（模型上下文协议）管理能力。

4. `Skill + SOP`（技能与标准流程）
   将现有本地技能扩展为可选择、可读文件、可运行脚本、可记录产物的技能运行时。

5. 多智能体执行
   在现有深度研究基础上补齐通用 `ReAct`（思考行动循环）、`Plan Execute`（计划执行）、`Flow`（流程编排）和动态重规划。

6. 多模态与工作区
   补齐图像生成、图片编辑、多模态检索、文件工作区和工具产物复用。

7. 数据分析能力
   补齐数据源元信息读取、`NL2SQL`（自然语言转 SQL）、表格问答、图表生成和查询安全控制。

8. 前端产品化
   将当前演示工作台升级为多工作区：聊天、文件问答、图像生成、数据分析、`MRAG`（多模态检索增强生成）、运营监控。

## 当前已落地

- 运行期工具产物登记：记录某次工具调用生成的报告、图片、文件或中间产物。
- 额度使用快照：历史运行详情会记录 `quota_usage`（额度使用）快照，把 `Agent`（智能体）运行、额度余额和预估消耗放在一起回放。
- 运行配置快照：`Agent`（智能体）配置后台会输出启用模型、`API`（接口）、系统提示词、`Advisor`（顾问）、`RAG`（检索增强生成）顺序和绘图配置的运行快照，并对密钥类字段脱敏。
- 受控执行器：工具并发、回放投影和后台任务被拒绝执行时，统一返回“系统繁忙”。
- 通用工具运行时：统一承载工具定义、调用命令、调用结果、启停状态和必填参数校验。
- 工具集合与场景视图：支持按工具名、来源、分类构建不同 `Agent`（智能体）场景下的可用工具集合。
- 工具批量执行：支持并发调用多个工具，并把成功、失败、耗时和参数写入运行账本。
- 结构化工具输出：统一支持摘要、正文、元数据、文件引用和产物编号，后续代码解释器、数据分析、图像生成、报告工具可以直接复用。
- `MCP`（模型上下文协议）管理底座：支持服务描述、服务启停、工具定义投影，并可以连接 `streamable_http`（流式 HTTP）和 `sse`（服务端事件）服务自动发现并缓存工具；管理状态会保存到本地运行态配置文件，服务重启后可以恢复已注册服务和工具缓存。
- `MCP`（模型上下文协议）工具主链路桥接：已缓存且启用的 `MCP`（模型上下文协议）工具会生成安全的 `mcp_*`（模型工具名）进入主 `Agent`（智能体）工具集合，模型调用时再映射回真实服务和工具名执行。
- 当前 `MCP`（模型上下文协议）入口已经复用通用工具运行时，并暴露为工具集合视图，原接口格式保持不变。
- `MCP`（模型上下文协议）调用运行时复用：同一个服务会复用已初始化客户端，并用串行锁保护工具调用；服务重新注册或启停时会清理旧运行时，避免配置变更后继续使用旧连接。
- 多智能体计划底座：新增计划生命周期、动态重规划、依赖流程分层和 `planning`（计划）工具运行时，支持后续 `ReAct`（思考行动循环）与 `Plan Execute`（计划执行）共同复用。
- 领域层 `Flow`（流程编排）执行服务：计划会按依赖分层逐批执行，步骤失败后可触发动态重规划，并已有测试覆盖正常分层执行和失败重规划。
- 实时流与历史回放已经输出结构化 `Plan + FlowStages`（计划与流程阶段）：不同任务类型会生成带执行角色、依赖关系和阶段分组的计划，前端执行过程面板会按阶段展示。
- 计划阶段状态推进：实时流和历史回放会输出 `flow_delta`（流程阶段变化）事件，展示阶段运行、完成和阻塞状态，让 `Plan Execute`（计划执行）过程不只停留在静态计划。
- 计划历史展示：前端会从 `plan_delta`（计划更新）和 `flow_delta`（流程阶段变化）中归并出计划版本，展示初始计划、重规划版本、步骤数、阶段数和推进状态。
- 历史回放重规划补齐：如果执行账本里出现工具失败但后续工具恢复成功，历史回放会补出 `REPLANNED`（已重规划）阶段和新版 `plan_delta`（计划更新），让回放与实时运行保持一致。
- 本地通用工具运行时：新增 `web_fetch`（网页抓取）、`data_analysis`（数据分析）、`report_tool`（报告工具）、`code_interpreter`（代码解释器）、`image_generation`（图像生成）、`multimodal_agent`（多模态工具）、`deep_search`（深度搜索）、`file_tool`（文件工具）、`script_runner`（脚本运行器）、`table_rag`（表格检索问答）和 `nl2sql`（自然语言转 SQL），统一走工具定义、结构化输出和运行时注册表。
- 受控代码执行：`code_interpreter`（代码解释器）默认使用 `analysis`（分析权限），只在显式传入 `workspace`（工作区权限）时扩大到工作区读写；实际权限档位会进入工具结果和运行快照，避免“能跑代码但边界说不清”。
- 手动技能文件工具：`manual-skills`（手动技能）现在除了 `read_skill`（读取技能）外，还支持 `read_skill_file`（读取技能文件）、`grep_skill_files`（检索技能文件）、`glob_skill_files`（按规则查找技能文件）和 `list_skill_directory`（列出技能目录），访问范围只限已注册技能目录。
- 手动技能可发现：后端 `/agent/capabilities`（智能体能力接口）会返回 `manualSkills`（手动技能清单），前端工作区空态可以展示技能名称和脚本数量，避免技能只藏在提示词里。
- 工具 `Schema`（参数结构）规范化：工具定义会自动补齐 `type/properties/required`（类型、属性集合、必填参数），并移除部分模型调用不稳定字段，让内置工具和 `MCP`（模型上下文协议）工具都能以更稳定的参数格式暴露给模型。
- 工具目录可视化：后端 `/agent/capabilities`（智能体能力接口）会返回 `toolCatalog`（工具目录），按分类、来源和工作区覆盖情况组织工具，前端能力条会展示工具分类数量。
- 端口化外部能力：代码执行、图像生成、多模态分析、深度搜索、文件读写、技能脚本运行、表格检索和自然语言转 SQL 都先沉淀为领域端口，后续可以接 `reactor-tool`（工具服务）、对象存储、搜索服务、数据查询服务或沙箱执行环境，不在领域层直接硬编码外部密钥或本机命令。
- 远端工具服务桥接增强：`reactor-tool`（工具服务）已覆盖代码解释器、自动数据分析、报告生成、网页读取、图像生成、多模态分析、深度搜索、文件读写、脚本运行、表格检索和 `NL2SQL`（自然语言转 SQL）；其中网页读取会带回完整正文文件产物，深度搜索会解析流式回答、子查询和搜索文档，文件接口兼容无状态码返回。
- 通用工具注册工厂：新增安全本地工具默认注册和外部端口完整注册两种方式，后续 `Agent`（智能体）主入口、`MCP`（模型上下文协议）入口和测试环境可以复用同一套工具集合。
- 主 `Agent`（智能体）链路接入：新增 `Spring AI ToolCallback`（工具回调）适配层，`ppt`（演示文稿）、`deep`（深度研究）、`skills`（技能）和 `manual-skills`（手动技能）会按会话动态挂载通用工具集合。未开启联网时不会挂载网页抓取和深度搜索，避免破坏原有联网开关语义。
- 能力状态面板：后端 `/agent/capabilities`（智能体能力接口）会返回模型、联网搜索、手动技能、参考工具服务和通用工具清单，前端工作台展示当前可用能力，避免演示时不知道哪些能力已接入。
- 前端 `MCP`（模型上下文协议）管理入口：工作台顶部新增 `MCP`（模型上下文协议）面板，支持保存运营授权、注册或更新服务、启停服务、一键发现工具、手动写入工具缓存和查看已发现工具，让后端 `MCP`（模型上下文协议）能力可以直接在产品界面演示。
- 前端工作区入口：新增轻量路径路由和侧边栏工作区导航，支持 `/workspace/image`（图像生成工作区）、`/workspace/data`（数据问答工作区）和 `/workspace/mrag`（多模态检索增强生成工作区）。这些工作区会走独立任务类型，后端分别挂载图像生成、数据分析、表格检索、多模态分析和自然语言转 SQL 等工具。
- 数据模型目录：数据问答工作区新增后端 `catalog`（目录）接口，默认提供交易订单、拼团锁单、额度账户和额度流水的表结构，前端进入数据工作区时可自动填充模型编码、字段列表和 `schemaInfo`（表结构信息）。
- 前端 `TypeScript`（前端类型语言）与测试底座：新增工作区路由模型 `workspaces.ts`（工作区类型模型）和 `vitest`（前端单测工具），覆盖工作区路径、任务模式、模板完整性，以及 `MCP`（模型上下文协议）管理接口的请求地址、请求体和运营授权头，后续页面拆分与类型迁移可以继续沿用。
- `MRAG`（多模态检索增强生成）知识库工作区增强：支持文件上传、网页地址导入、知识库目录聚合、文档片段查看、文档全文预览和文档软下线；下线文档的片段会同步禁用，检索回查时只使用仍启用的片段。
- 工作区历史运行详情：用户从图像、数据和 `MRAG`（多模态检索增强生成）历史任务进入会话时，会同步读取本次运行详情，展示运行状态、工具调用、产物数量、摘要和错误信息，让工具产物和执行账本可以直接在前端回放。
- `Agent`（智能体）执行模式显式化：后端能力接口会返回 `agentExecutionModes`（智能体执行模式清单），前端选择器直接标明 `ReAct`（思考行动循环）、`Plan`（计划执行）、`Flow`（流程编排）和 `Skill`（技能流程），让多智能体能力不只停留在代码实现里。
- 能力矩阵前端可视化：前端会展开展示 `capabilityMatrix`（能力矩阵）的就绪状态、证据和缺口，并同时展示各 Agent 执行模式，方便演示当前系统已经具备的运行时、工具、`MCP`（模型上下文协议）、工作区和交易闭环能力。

## 面试表达

这个方向不要讲成“把参考项目全搬过来”，而是讲成：

> 在原有额度、拼团和支付闭环之上，继续抽象 `Agent`（智能体）运行时，把工具调用、产物生成、执行账本和历史回放沉淀成通用底座，使业务交易系统和智能体执行系统可以互相校验。
