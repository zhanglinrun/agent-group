# 导购融合拼团试算

## 一、目标

本阶段把拼团活动试算接入导购决策流程。

用户咨询商品时，导购先读取推荐商品，再按商品编号查询拼团活动，最后把拼团价、成团人数、剩余时间写入商品卡片。

当前仍不创建订单、不锁定拼团名额，也不处理支付。

## 二、调整后的链路

```text
用户问题
-> 意图识别
-> 商品和知识片段查询
-> 拼团活动试算
-> 生成推荐结果
-> 输出商品卡片和回答片段
```

## 三、商品卡片更新规则

- 拼团活动可用时，商品卡片使用试算结果里的活动编号、拼团价、成团人数和剩余秒数。
- 拼团活动不可用时，商品卡片保留原商品信息；如果没有拼团价，则用原价作为展示价。
- 成团人数缺失时，默认按 1 人处理，避免前端展示空值。
- 剩余秒数缺失时，默认按 0 处理。

## 四、推荐理由更新

当用户问题关注拼团时，导购会额外加入拼团试算理由：

- 活动可用：说明成团人数和剩余时间。
- 活动不可用：说明未配置、未开始、已结束或已停用。

## 五、测试范围

已更新 `GuideDecisionServiceTest`（导购决策服务测试）和 `AgentGuideStreamServiceTest`（导购流式服务测试）。

测试覆盖：商品卡片使用拼团试算结果、拼团关注问题生成拼团试算理由、流式商品卡片仍可正常渲染。
