# 商品和导购领域模型

## 一、目标

本阶段把导购接口里的“返回一个写死推荐商品”，整理成可继续扩展的领域对象。

当前仍然使用 `MySQL`（关系型数据库）里的初始化商品、活动和知识片段，不接真实大模型，不引入新的交易流程。

## 二、新增对象

| 对象 | 含义 |
| --- | --- |
| `GuideIntent`（导购意图） | 记录用户当前问题的意图类型，比如商品推荐、商品对比、拼团规则、售后咨询。 |
| `UserRequirement`（用户需求） | 从意图里整理出的用户身份、使用场景、预算敏感、拼团关注和售后关注。 |
| `RecommendationReason`（推荐理由） | 把推荐依据拆成可追踪的结构化理由，包含理由类型、内容和权重。 |
| `RecommendationResult`（推荐结果） | 保存主推商品、候选商品、推荐理由和结果自检状态。 |
| `GuideDecisionResult`（导购决策结果） | 统一返回意图、用户需求、知识引用、推荐结果、商品卡片和回答片段。 |

## 三、当前链路

```text
用户问题
-> 识别 GuideIntent（导购意图）
-> 整理 UserRequirement（用户需求）
-> 读取知识引用和推荐商品
-> 生成 RecommendationResult（推荐结果）
-> 输出 answer_delta、product_card、self_check 等流式事件
```

## 四、自检规则

当前自检先做基础完整性检查，避免商品卡片缺少核心字段：

- 商品编号和商品名称不能为空。
- 原价和拼团价不能为空。
- 规格摘要不能为空。
- 推荐理由不能为空。

后续接入多商品推荐和大模型回答后，自检会继续扩展到价格一致性、规格一致性和推荐理由一致性。

## 五、测试范围

已在 `backend/agent-group-app/src/test/java`（后端测试目录）补充测试：

- `GuideDecisionServiceTest`（导购决策服务测试）：覆盖意图识别、用户需求整理、推荐理由生成、空问题异常、无商品异常、商品资料不完整自检。
- `AgentGuideStreamServiceTest`（导购流式服务测试）：覆盖流式事件顺序、商品卡片渲染数据和自检事件。
