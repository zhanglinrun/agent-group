# 导购接口契约

## 一、接口目标

本接口用于固定用户端和后端之间的导购流式返回格式。本阶段从 MySQL 读取商品、活动和知识片段数据，后续接入意图识别、向量检索、拼团试算和大模型回答时，前端仍按同一套事件渲染。

本阶段不接真实大模型、不处理真实交易，只先把导购过程中的事件结构和本地数据源固定下来。

## 二、接口地址

```text
POST /api/v1/agent/guide/stream
```

返回类型：

```text
text/event-stream
```

## 三、请求参数

| 字段 | 含义 | 是否必填 | 说明 |
| --- | --- | --- | --- |
| sessionId | 会话编号 | 否 | 前端没有传时，后端生成一个临时会话编号。 |
| userId | 用户编号 | 否 | 当前先使用模拟用户。 |
| question | 用户问题 | 是 | 用户输入的导购问题。 |
| imageUrl | 图片地址 | 否 | 预留给后续图片输入解析。 |

## 四、事件外壳

每一条流式消息都使用同一层事件外壳。

| 字段 | 含义 |
| --- | --- |
| event | 事件类型。 |
| sessionId | 会话编号。 |
| requestId | 本次请求编号。 |
| sequence | 事件序号，从 1 开始递增。 |
| timestamp | 事件生成时间。 |
| data | 当前事件的数据内容。 |

## 五、事件类型

| 事件 | 含义 | 前端处理方式 |
| --- | --- | --- |
| tool_call | 工具调用过程 | 展示“正在识别意图、检索知识”等过程消息。 |
| reference_delta | 知识引用 | 追加展示命中的知识片段。 |
| answer_delta | 回答片段 | 追加到当前回答气泡中。 |
| product_card | 商品卡片 | 渲染商品卡片。 |
| order_delta | 订单状态 | 更新交易时间线，本阶段只保留契约。 |
| self_check | 结果自检 | 展示回答依据和商品卡片一致性检查结果。 |
| done | 完成 | 结束本轮流式输出。 |
| error | 错误 | 展示错误原因并结束本轮输出。 |

## 六、本阶段固定事件顺序

本阶段后端按以下事件顺序返回，知识引用和商品卡片来自本地 MySQL 初始化数据。

```text
tool_call
reference_delta
reference_delta
reference_delta
answer_delta
answer_delta
product_card
self_check
done
```

如果用户问题为空，则直接返回：

```text
error
```

如果本地数据源未启动或商品数据未初始化，也会返回 `error`。

## 八、前端渲染约定

前端只根据 `event` 字段判断怎么渲染，不从回答正文中解析商品、价格和依据。

- 收到 `answer_delta` 时，追加回答文字。
- 收到 `reference_delta` 时，追加知识依据。
- 收到 `product_card` 时，渲染商品卡片。
- 收到 `self_check` 时，展示自检消息。
- 收到 `done` 时，结束本轮输出。
- 收到 `error` 时，展示错误原因并结束本轮输出。
