# 多模式 Agent 工作台与拼团式额度交易平台简历材料

## 技术栈

Java 21、Spring Boot、Spring AI、MySQL、Redis、RabbitMQ、MyBatis、PostgreSQL、MinIO、XXL-JOB

## 项目描述

面向内容生成与额度交易场景开发的多模式 Agent 工作台，支持智能问答、文件理解、联网搜索、深度任务规划、PPT 生成和技能调用。系统通过统一 Agent Runtime 管理模式路由、上下文注入、记忆加载、工具调用、流式响应和运行追踪，并围绕 Agent 调用额度构建拼团购买、支付结算、额度发放、消息投递和补偿任务链路。

## 负责功能

1. Agent Runtime 设计：设计统一运行时入口，收敛请求解析、用户上下文、额度校验、模式选择、工具注入、SSE 流式响应、运行 trace 和会话持久化，避免不同 Agent 重复实现通用执行流程。

2. 多模式 Agent 路由：实现 auto 模式选择，根据用户问题、显式模式、附件类型和任务分析结果路由到普通问答、文件问答、联网搜索、深度规划和 PPT 生成链路；路由测试覆盖 23 条用例，准确率超过 90%，后续扩展到 X 条样本。

3. 记忆与文件理解：实现用户长期记忆、运行过程记忆和文件向量记忆，整合历史消息、任务步骤、文件解析结果和 PostgreSQL 检索结果；文件解析产物存储到 MinIO，多轮上下文命中率从 X 提升到 X。

4. 技能加载与重规划：设计文件系统 Skill 加载机制，支持技能元数据解析、脚本发现、目录读取和内容检索，当前可加载 14+ 项项目技能；深度任务失败后按工具缺失、参数错误、超时等原因重建计划，重试成功率达到 X。

5. 拼团交易链路：围绕 Agent 调用额度设计拼团购买流程，覆盖活动试算、库存校验、锁单参团、支付回调、组队成团和成团发额；通过订单状态区分支付成功、等待成团和额度到账，避免未成团订单提前发放额度。

6. 交易一致性与补偿：基于 RabbitMQ 和 Outbox 投递交易事件，使用 XXL-JOB 承载拼团通知、超时退款和支付查单补偿；结合支付幂等、订单流水、额度流水、Redis 分布式锁和重试死信机制，压测 QPS 达到 X，P99 为 X ms。

## 指标补充位

- 路由评测：当前 23 条用例，准确率超过 90%；后续补充 X 条样本、整体准确率 X、关键场景召回率 X。
- 记忆效果：后续补充多轮上下文命中率、用户偏好命中率或人工验收通过率。
- 文件问答：后续补充召回率、命中率、MRR 或人工评测通过率。
- 重规划：后续补充失败重试成功率、平均重规划轮次和异常恢复率。
- 交易压测：后续补充拼团锁单和直接购买链路的 QPS、P95、P99、错误率。

## 面试表达提醒

- 不写 Kafka，本项目实际使用 RabbitMQ。
- 不写 Spring WebFlux，当前代码是 Spring MVC + Reactor Flux 做流式响应。
- 不把 PPT 生成包装成标准 Agent 架构模式，可以说成 PPT 状态机生成链路。
- 不写“技能编排”的英文包装，代码里更准确的是文件系统 Skill 动态加载与工具注入。
- 拼团交易是项目第二主线，至少讲两点：交易主链路和一致性补偿。
- 未实测的 QPS、P99、召回率等数字先用 X 占位，不编造。
