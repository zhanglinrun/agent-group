# 项目复盘：电商可信导购 Agent

## 一句话定位

我做的不是普通电商增删改查，而是基于 `Spring AI`（Spring 人工智能框架）把 `AI Agent`（人工智能智能体）接到真实交易链路里：模型只负责理解意图和组织回答，价格、拼团、订单、售后这些高风险信息都必须由后端工具和知识库提供。

## 为什么这样设计

普通 `RAG`（检索增强生成）导购容易停留在“检索几段文档再回答”，面试时会被认为像演示项目。这个项目把导购回答接到商品、活动、订单和支付状态上，核心难点变成三件事：

1. 大模型不能编造价格、库存和订单状态。
2. 拼团、支付、退款这些状态要能幂等处理和补偿。
3. 回答质量要能被评测和监控，而不是只靠人工感觉。

## 我重点解决的问题

1. 工具治理：把知识检索、商品推荐、拼团试算、订单查询封装成后端工具，并为每个工具维护版本、风险等级、重试次数、结果引用要求和执行审计，模型只能选择白名单工具，不能直接访问任意接口。
2. 流式可解释：前端实时展示工具计划、工具调用、检索依据、商品卡片和回答内容，让用户知道系统查了什么。
3. 交易一致性：拼团锁单、支付回调、成团结算、退款补偿都围绕订单状态流转设计，避免重复扣款和重复占名额。
4. 知识库治理：上传文档后进入对象存储、文本解析、知识切片、`Spring AI VectorStore`（向量存储接口）检索链路；查询时融合向量召回和关键词召回，再按业务关键词重排，保证商品编号、拼团、退款、售后这类事实优先命中。
5. 质量评测：用评测用例检查检索命中、回答准确、推荐合理、多轮一致、工具调用、工具参数和工具结果引用，并设置回归门禁。
6. 可观测性：接入工具调用次数、工具耗时、模型耗时、向量检索回退等指标，能解释慢在哪里、错在哪里。

## 面试讲法

如果面试官问“这个项目和培训班项目有什么区别”，可以这样回答：

“我没有只做一个聊天页面，而是把大模型导购接到了交易系统里。比如用户问拼团价，模型不能直接回答，必须先规划 `group_trial`（拼团试算）工具，再由后端根据真实商品编号查活动服务，最后答案和商品卡片都用同一份试算结果。订单状态同理，只能走 `order_status`（订单状态查询）工具，避免模型幻觉。”

如果面试官问“怎么证明效果”，可以回答：

“我做了离线评测集，覆盖商品推荐、拼团报价、售后规则、订单查询和多轮追问。每批评测会产出检索命中率、回答准确率、推荐合理率、工具调用正确率、工具参数正确率和工具结果引用率，并设置工具调用正确率、工具结果引用率、回答准确率的回归门禁。不是只看一次演示，而是能持续对比版本效果。”

如果面试官问“工程上有哪些兜底”，可以回答：

“知识向量库不可用时有本地检索兜底，大模型接口不可用时有基于商品资料和知识片段的兜底回答；支付回调有防重放，拼团锁单有幂等键，交易事件用 `Outbox`（事务消息表）和补偿任务降低状态不一致风险。”
