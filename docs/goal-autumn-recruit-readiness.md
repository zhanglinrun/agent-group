# Goal: 2027 届大厂秋招项目完善与验收

Objective:
按 2027 届计算机硕士大厂秋招后端 / `AI`（人工智能）开发面试标准，系统性检查、修复并完善本项目，使“学术 `Agent`（智能体）平台 + 额度交易一致性系统”具备可运行、可演示、可测试、可复述的项目证据。

First action:
先读取 `AGENTS.md`（项目规则）、`README.md`（项目说明）、`docs/autumn-recruit-project-overview.md`（秋招总览）、`docs/agent-platform-upgrade.md`（平台升级路线）、`backend/pom.xml`（后端父级配置）、`frontend/package.json`（前端配置），然后回报：
- 识别到的后端模块数量。
- 识别到的前端工作区 / 页面入口数量。
- `Done when`（完成条件）数量。
- `Stop if`（停止条件）数量。
回报后继续执行，除非已经命中 `Stop if`（停止条件）。

Scope:
- 后端范围：`backend`（后端目录）下的 `agent-group-api`（接口模块）、`agent-group-app`（应用模块）、`agent-group-domain`（领域模块）、`agent-group-infrastructure`（基础设施模块）、`agent-group-trigger`（入口模块）、`agent-group-types`（通用模块）。
- 前端范围：`frontend`（前端目录）下用户端 `Agent`（智能体）工作台、额度 / 交易页面、运营后台、`MCP`（模型上下文协议）管理入口、图像生成工作区、数据问答工作区、`MRAG`（多模态检索增强生成）工作区。
- 文档范围：`README.md`（说明文档）、`docs`（文档目录）中秋招总览、演示脚本、运行检查、评测证据和项目复盘类文档。
- 允许新增必要的测试、演示检查脚本、运行验证文档和小范围修复。
- 不做大规模重构，不拆微服务，不改项目定位，不把项目泛化成普通聊天机器人。

Constraints:
- 默认一次性完成当前任务，再汇报结果；不要只给方案。
- 所有输出默认使用简短自然的中文；非中文术语按项目规则写成 `英文内容`（中文解释）。
- 文件路径在汇报中只写正常文本，不做成可点击链接。
- 不提交、不打印、不硬编码密码、令牌、`API Key`（接口密钥）或 `.env`（环境变量文件）。
- 不修改 `.env`（环境变量文件）和 `.env.local`（本地环境变量文件），也不要把它们加入 `Git`（版本控制工具）。
- 额度只能由后端交易状态发放；前端和 `Agent`（智能体）不能决定额度到账。
- 拼团支付成功不等于额度到账；必须等 `GROUP_SETTLED`（拼团已成团）或 `DEAL_DONE`（交易完成）后才能发放额度。
- 涉及订单、支付、拼团、退款和额度流水的结论，必须来自后端交易记录、额度账本或管理端核查结果。
- 大模型主链路优先使用 `Spring AI ChatClient`（聊天客户端）、`EmbeddingModel`（向量模型接口）和 `VectorStore`（向量存储接口），手写客户端只作为回退链路。
- 前端修复要保持现有产品风格，不重写整套页面，不做营销落地页。
- 不新增重依赖；如果必须新增依赖，先停止并说明原因。
- 不通过删除测试、跳过测试或弱化断言来制造通过。
- 若存在用户未提交改动，必须保留并协同处理，不得回滚。

Done when:
1. 后端模块有效性已验证：运行 `cd backend && mvn -pl agent-group-app -am test`，退出码为 0，并在最终汇报中写出测试总数、失败数、跳过数。
2. 后端全量编译已验证：运行 `cd backend && mvn clean compile`，退出码为 0；如失败，必须定位到具体模块并修复，不能只记录失败。
3. 前端静态验证已完成：运行 `cd frontend && npm test`、`cd frontend && npm run build`，退出码均为 0，并在最终汇报中写出测试数量和构建结果。
4. 前端主要页面可运行：启动后端和前端，在浏览器中实际打开用户端、运营后台、图像生成工作区、数据问答工作区、`MRAG`（多模态检索增强生成）工作区、`MCP`（模型上下文协议）管理入口，确认页面无白屏、无明显报错、核心信息可见。
5. 对话链路可运行：通过浏览器或接口完成一次普通学术对话，确认能返回内容、能展示流式或准流式结果、能记录会话 / 运行摘要，并确认失败时有可理解的回退提示。
6. 技能调用可运行：至少验证一个本地 `Skill`（技能）或手动技能读取 / 调用链路，确认技能可发现、可读取、可被工具运行时记录结果。
7. 生图链路可运行：在图像生成工作区完成一次图片生成请求；如果缺少真实模型密钥或外部服务不可用，必须确认前端状态、后端错误语义、回退提示和运行账本都正确，不能把不可用伪装成成功。
8. 交易主路径可验证：至少覆盖直购支付成功到账、拼团支付成功但未成团不到账、拼团成团到账、退款后额度回滚、重复回调幂等这 5 类场景；可通过已有测试、接口模拟或补充测试证明。
9. 后台核查可验证：运营端或后端接口能展示订单事实、支付事实、拼团事实、退款事实、额度流水、异常标记和建议结论，且文案区分“支付成功，等待成团”和“额度已到账”。
10. `Agent`（智能体）工程化证据完整：运行回放能展示计划、工具调用、结果观察、产物、额度使用快照；能力面板能展示模型、工具、`MCP`（模型上下文协议）、工作区和交易护栏状态。
11. 秋招表达材料已更新：`README.md`（说明文档）、`docs/autumn-recruit-project-overview.md`（秋招总览）或 `docs/autumn-recruit-demo-script.md`（演示脚本）至少一处更新，内容聚焦“学术 `Agent`（智能体）平台 + 额度交易一致性系统”，避免写成技术栈堆砌。
12. 生成一份最终验收文档，建议路径为 `docs/autumn-recruit-readiness-report.md`（秋招就绪报告），包含：已验证模块、实际命令结果、浏览器检查结果、仍需真实外部配置支持的项、面试可讲亮点和剩余风险。
13. 最终汇报列出本轮修改文件、验证命令、通过 / 失败结果、未能真实验证的外部依赖项，并确认没有提交 `.env`（环境变量文件）或任何密钥。

Stop if:
- 需要新增或泄露真实密钥、支付私钥、模型 `API Key`（接口密钥）、令牌或 `.env`（环境变量文件）。
- 需要调用真实扣款、真实退款、真实外部支付生产环境。
- 需要新增重依赖或升级 `Java`（后端语言）、`Spring Boot`（后端框架）、`Spring AI`（Spring 人工智能框架）、`React`（前端框架）主版本。
- 需要大规模重写前端、拆分微服务、迁移数据库类型或改变项目主定位。
- 外部模型、支付宝沙箱、对象存储、向量库、`RabbitMQ`（消息队列）等真实服务缺失，且本地无法通过模拟 / 降级链路继续验证核心行为。
- 现有测试出现回归，且修复需要删除测试、跳过测试或弱化断言。
- 发现 `Git`（版本控制工具）中已有用户未提交改动与本任务直接冲突，且无法在不覆盖用户改动的前提下继续。
- 浏览器验证发现大量页面白屏或后端无法启动，且连续三次定位仍无法取得新的有效进展。
- 运行验证需要超过当前机器可承受的资源或导致本地服务持续不可用。
